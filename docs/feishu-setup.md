# 飞书应用配置

本文只讲飞书开发者后台。第一次部署请从[从零部署指南](deployment.md)开始，避免漏掉本机依赖、Codex 登录和启动验证。

飞书配置分为四类，缺一类会呈现不同故障：

| 配置 | 决定什么 | 缺失时的表现 |
|---|---|---|
| 机器人能力 | 应用能否作为机器人使用 | 找不到机器人或机器人信息检查失败 |
| API 权限 | 能否读群成员、发消息、上传/下载文件 | 能收到事件，但发送或附件操作报权限错误 |
| 事件订阅 | 飞书是否把消息、进群等事件推给服务 | 机器人完全收不到消息 |
| 卡片回调 | 按钮点击是否推给服务 | 文字能回复，但卡片按钮无反应 |

## 1. 创建企业自建应用

1. 打开[飞书开放平台开发者后台](https://open.feishu.cn/app)。
2. 创建“企业自建应用”，填写应用名称、描述和图标。
3. 在“添加应用能力”或“应用能力”中启用“机器人”。
4. 在“凭证与基础信息”复制 App ID 和 App Secret。
5. 将凭证只写入部署机器的 `.env`；不要写入代码、截图、群聊或 Issue。

```dotenv
FEISHU_APP_ID=
FEISHU_APP_SECRET=
```

```bash
chmod 600 .env
./start.sh doctor
```

## 2. 申请 API 权限

进入“权限管理”，权限身份选择“应用身份”。推荐的常规部署组合是：

- `im:message`
- `im:message.p2p_msg:readonly`
- `im:message.group_at_msg:readonly`
- `im:message.group_msg`
- `im:chat.members:read`
- `im:chat.members:bot_access`
- `im:resource`

其中 `im:message.group_msg` 属于敏感权限，用于读取群内普通消息并支持单真人群免 `@`。不申请它也能使用机器人，但群聊应始终 `@机器人`。如果企业要求最小粒度或不允许综合权限，请使用[飞书权限、事件与回调清单](feishu-permissions.md)中的替代组合。

不使用多维表格控制台时，不要申请 `bitable:*` 或云文档事件权限，也不要填写 `.env` 中的 `FEISHU_BITABLE_*`。

## 3. 配置消息事件长连接

进入“事件与回调 → 事件配置”：

1. 订阅方式选择“使用长连接接收事件”。
2. 添加“接收消息 v2.0”：`im.message.receive_v1`，这是必需事件。
3. 添加“机器人进群”：`im.chat.member.bot.added_v1`，用于自动创建工作区和欢迎语。
4. 可选添加“消息撤回”：`im.message.recalled_v1`；当前项目只静默接收它。

长连接不需要公网域名、HTTPS 证书或回调 URL，但运行机器必须持续在线并能主动访问飞书。部分后台在保存长连接配置时会检查客户端是否已经连接；如果看到“应用未建立长连接”之类的提示：

```bash
./start.sh
```

保持命令运行，再回到后台刷新、选择长连接并保存。完成后可按 `Ctrl-C`，再改用 tmux 或 autostart。

## 4. 配置卡片回调长连接

进入“事件与回调 → 回调配置”：

1. 投递方式选择“使用长连接接收回调”。
2. 添加“卡片回传交互”：`card.action.trigger`。
3. 保存配置。

这不是 `im.message.receive_v1` 的一部分。项目的停止、重启、模型选择、控制面板和隐私确认按钮都依赖这个回调。回调本身不要求额外 API scope，但服务应及时返回响应。

## 5. 创建版本并发布

1. 进入“版本管理与发布”，创建新版本。
2. 确认本次新增的权限、事件和回调均包含在版本中。
3. 设置可用范围，确保测试账号和目标群成员在范围内。
4. 提交审核并发布；没有管理员权限时请企业管理员完成审批。
5. 发布完成后，再运行一次 `./start.sh doctor`。

每次新增权限后都应检查是否需要发布新版本。仅在“权限管理”里勾选但未发布，线上机器人通常仍不能使用新权限。

## 6. 添加机器人并验收

先用私聊做最小验证，再进入群聊：

1. 私聊发送 `/help`，应出现控制面板卡片。
2. 点击控制面板按钮，应看到卡片更新。
3. 私聊发送普通问题，应收到 Codex 回复。
4. 发送 `/status`，检查链路和服务状态。
5. 把机器人加入测试群。
6. 多人群中普通消息应被忽略；`@机器人` 后应回复。
7. 发送图片或文件并补充要求，验证上传、下载和发送资源权限。

单真人群免 `@` 依赖 `im:message.group_msg` 和 `im:chat.members:read`。如果成员读取失败，项目会采用更保守的多人群行为，只响应 `@机器人`，避免在真实多人群中误触发。

## 7. 可选：多维表格控制台

只有需要通过多维表格统一管理群配置时才启用：

1. 申请 `bitable:app` 和所需云文档事件权限。
2. 将该应用添加为目标多维表格的文档应用，授予资源访问权。
3. 在 `.env` 同时填写 `FEISHU_BITABLE_APP_TOKEN` 与 `FEISHU_BITABLE_TABLE_ID`。
4. 添加 `drive.file.bitable_record_changed_v1` 事件。
5. 按飞书云文档事件机制订阅目标文档。
6. 重启 Server 和 Scheduler，再发送 `/sync` 验证。

两项环境变量任意一项为空时，多维表格功能不会启用，不影响聊天功能。

## 8. 配置变更后的固定动作

每次修改权限、事件或回调后，按这个顺序检查：

```bash
./start.sh doctor
./start.sh tmux restart
./start.sh tmux status
./start.sh tmux logs
```

然后确认飞书新版本已经发布，并重新测试 `/help`、卡片按钮和普通问题。仍有问题时查看[故障排查](troubleshooting.md)。
