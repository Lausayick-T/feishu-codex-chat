# 飞书应用操作流程

## 1. 创建应用

1. 登录飞书开放平台，进入“开发者后台”。
2. 创建企业自建应用。
3. 在“添加应用能力”中启用“机器人”。
4. 从“凭证与基础信息”复制 App ID 和 App Secret，写入本机 `.env`。

不要把 App Secret 发到群里、写入截图、提交到 Git 或粘贴进 Issue。

## 2. 配置权限

在“权限管理”中申请 [飞书权限清单](feishu-permissions.md) 中的权限。权限变更后需要创建新版本并发布，未发布的权限不会生效。

## 3. 配置事件

在“事件与回调”中：

1. 事件订阅方式选择“使用长连接接收事件”。
2. 添加 `im.message.receive_v1`。
3. 如需自动欢迎新群，添加 `im.chat.member.bot.added_v1`，并申请 `im:chat.members:bot_access`。
4. 如需多维表格配置同步，添加 `drive.file.bitable_record_changed_v1`，并完成目标文档的事件订阅和资源授权。

长连接模式不需要公网 URL，但服务进程必须持续在线并能够访问飞书开放平台。

## 4. 配置卡片回调

交互卡片按钮使用的是“回调”通道，不是普通事件订阅。订阅 `card.action.trigger`，并把回调投递方式也设置为长连接，否则停止、重启、模型选择和控制面板按钮不会生效。该回调没有额外 API scope，但需要在 3 秒内响应。

## 5. 发布应用

1. 创建应用版本。
2. 提交企业管理员审核。
3. 发布后确认权限状态已经生效。
4. 将机器人添加到目标群，或直接与机器人私聊。

## 6. 启动和验证

```bash
uv sync --locked
./start.sh doctor
./start.sh tmux start
./start.sh tmux status
./start.sh tmux logs
```

建议依次验证：

1. 私聊发送 `/help`，应出现控制面板。
2. 单真人群直接发消息，应获得回复。
3. 多真人群不 `@` 时应忽略，`@机器人` 后应回复。
4. 发送图片后补充处理要求，应能读取附件。
5. 点击控制面板按钮，确认卡片回调生效。
6. 发送 `/status`，确认飞书链路、Codex 和调度服务状态。
7. 发送 `/privacy`，确认当前会话的数据清单和保留策略可见。

## 7. 常见问题

- 收不到消息：检查事件是否选择长连接、应用版本是否发布、机器人是否进群。
- 能收不能发：检查消息发送权限。
- 群里必须 `@`：这是多人群的预期行为；单真人群需要成员读取权限才能自动识别。
- 卡片按钮无反应：检查回调通道是否也配置为长连接。
- Codex 一直启动：在服务器上执行 `codex doctor` 或重新登录。
